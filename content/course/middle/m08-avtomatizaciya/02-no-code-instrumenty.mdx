Каждое утро PM портала открывает трекер, фильтрует просроченные задачи и пишет исполнителям в
мессенджер. Двадцать минут в день, почти два часа в неделю. Эту работу может делать сценарий:
проверить трекер, найти просрочки, отправить сообщение. Для этого не нужно программировать —
достаточно понять, из каких блоков строится автоматизация.

## Триггер — условие — действие

Любой no-code сценарий состоит из трёх типов блоков:

- **Триггер** — событие, которое запускает сценарий: задача сменила статус, пришло письмо,
  наступило 9:00 понедельника.
- **Условие** — фильтр: только задачи с типом «Ошибка», только если срок прошёл, только для
  проекта «Портал».
- **Действие** — что сделать: отправить сообщение, создать задачу, записать строку в таблицу,
  вызвать ИИ для обработки текста.

Пример сценария напоминаний о просрочках:

<Steps>
1. **Триггер:** каждый рабочий день в 9:30.
2. **Действие:** запросить в трекере задачи проекта со сроком раньше сегодняшнего и статусом не
   «Готово».
3. **Условие:** если задач нет — завершить.
4. **Действие:** сгруппировать задачи по исполнителям.
5. **Действие:** отправить каждому исполнителю личное сообщение со списком его просроченных задач.
6. **Действие:** отправить PM сводку: сколько просрочек, у кого.
</Steps>

<Callout type="important" title="Сначала нарисуйте сценарий на бумаге">
Прежде чем открывать инструмент, опишите сценарий по шагам: что запускает, какие условия, какие
действия, что делать при ошибке. Половина проблем находится на этом этапе.
</Callout>

## Встроенные автоматизации трекеров

Многие трекеры и корпоративные порталы имеют встроенные правила: «при переходе в статус X назначить
Y», «при создании задачи типа Z добавить чек-лист», «за день до срока напомнить исполнителю».

Плюсы: не нужны отдельные сервисы и доступы, данные не уходят наружу. Минусы: работают только
внутри одного сервиса.

Начинайте со встроенных возможностей — часто их достаточно.

## Сервисы интеграций и платформы автоматизации

Когда сценарий связывает несколько сервисов — трекер, мессенджер, таблицу, почту, — нужны сервисы
интеграций. Примеры (названия приведены как примеры, возможности меняются):

- **Albato** — российский сервис no-code интеграций с набором готовых коннекторов к популярным
  сервисам; работает в облаке.
- **n8n** — платформа автоматизации с визуальным редактором сценариев; её можно развернуть на своём
  сервере, и тогда данные не покидают инфраструктуру компании.

| Вариант | Когда подходит | Что учесть |
|---|---|---|
| Встроенные автоматизации | Сценарий внутри одного сервиса | Ограниченные возможности |
| Облачный сервис интеграций | Несколько сервисов, быстрый старт | Данные проходят через сервис; политика компании |
| Платформа на своём сервере | Чувствительные данные, сложные сценарии | Нужен кто-то, кто поддерживает сервер |

## Боты в мессенджерах для команды

Бот в рабочем мессенджере — удобный канал для уведомлений и простых действий: напоминания,
сводки, сбор статусов по кнопке («Всё по плану» / «Есть риск» / «Заблокировано»). Многие команды
используют для этого Telegram; если в компании принят другой мессенджер — используйте его.

Правила для ботов:

- **Не спамить.** Одна сводка в день лучше двадцати уведомлений.
- **Личное — лично.** Просрочки конкретного человека — в личные сообщения, а не в общий чат.
- **Кнопки вместо текста** там, где ответ стандартный.
- **Данные.** Уточните, разрешено ли передавать через этот мессенджер рабочую информацию.

## ИИ как шаг сценария

В сценарий можно встроить обращение к языковой модели: например, после сбора статусов подрядчика
модель делает сводку, а сценарий отправляет её PM. Правила те же, что для любой работы с ИИ: только
разрешённые сервисы, обезличенные данные, а результат, который уходит наружу, проверяет человек.

<Callout type="mistake" title="Модель в конце цепочки без проверки">
Сценарий «собрал статусы → модель написала отчёт → отправил директору» однажды отправит выдуманную
причину задержки. Делайте последний шаг для внешних адресатов ручным: сценарий готовит черновик, PM
проверяет и отправляет.
</Callout>

## Практика

Спроектируйте сценарий напоминаний о просроченных задачах для своего трекера или учебного портала:
триггер, условия, действия, куда уходят сообщения, что происходит при ошибке. Выберите инструмент —
встроенные автоматизации, облачный сервис или свой сервер — и обоснуйте выбор с учётом данных.

<KeyTakeaways>
- Сценарий строится из триггеров, условий и действий; сначала опишите его на бумаге.
- Начинайте со встроенных автоматизаций трекера — данные не уходят наружу.
- Для связки сервисов — облачные сервисы интеграций или платформы на своём сервере.
- Боты в мессенджере: без спама, личное — лично, кнопки для стандартных ответов.
- ИИ может быть шагом сценария, но то, что уходит внешним адресатам, проверяет человек.
</KeyTakeaways>
