Финансовый директор просит бюджет портала для дилеров «на одну страницу к четвергу». PM берёт оценку
команды в человеко-месяцах, умножает на ставку и получает цифру. Через полгода выясняется, что в ней
нет лицензий, серверов, доработки учётной системы у подрядчика, обучения менеджеров и ни копейки на
риски. Проект не перерасходовал бюджет — бюджет просто был неполным с самого начала.

## Из чего складывается бюджет

| Статья | Что входит | Пример для портала |
|---|---|---|
| Трудозатраты команды | Время внутренних сотрудников по ставке | Разработчики, аналитик, дизайнер, PM |
| Подрядчики | Работы по договорам | Интеграция с учётной системой, доработка у поставщика |
| Закупки | Лицензии, оборудование, сервисы | Хостинг, сертификаты, платные компоненты |
| Эксплуатация на время проекта | Тестовые среды, инструменты | Тестовый стенд, трекер |
| Обучение и внедрение | Материалы, обучение пользователей | Инструкции и вебинары для дилеров |
| Резерв на риски | Деньги на известные риски | Задержка подрядчика, доработки после пилота |
| Управленческий резерв | Деньги на непредвиденное | Процент от бюджета по правилам компании |

Проверьте бюджет по WBS: у каждого пакета работ должен быть источник затрат. Если пакет есть, а
денег на него нет, — бюджет неполный.

## Оценка снизу вверх и по аналогии

**Снизу вверх.** Оценивают каждый пакет работ WBS — трудозатраты, закупки, подрядчиков — и
суммируют. Точнее всего, но требует детальной WBS и времени.

**По аналогии.** Берут фактическую стоимость похожего проекта и корректируют на отличия: «Портал для
дистрибьютора в прошлом году стоил X, у нас на треть больше функций и нет готовой интеграции».
Быстро, подходит для ранней оценки, но зависит от наличия данных.

**Параметрическая оценка.** Используют стоимость единицы: «настройка одного дилера — N рублей,
дилеров 400». Работает для повторяемых работ.

На старте обычно делают оценку по аналогии с широким диапазоном, а по мере детализации WBS —
уточняют снизу вверх.

<Callout type="important" title="Называйте точность оценки">
Ранняя оценка может отличаться от итога в разы, детальная — на десятки процентов. Сообщайте
диапазон и стадию: «Оценка по аналогии, диапазон от X до 1,6X. Уточним после детализации
требований через месяц».
</Callout>

## Резервы

**Резерв на риски** (contingency reserve) — деньги на известные риски из реестра. Его размер
обосновывают реестром: какие риски покрывает, сколько стоит их срабатывание с учётом вероятности.
Управляет им обычно PM в рамках согласованных правил.

**Управленческий резерв** (management reserve) — деньги на непредвиденное, «неизвестные
неизвестные». Его размер часто задают правилами компании. Распоряжается им спонсор или
руководство; PM запрашивает его с обоснованием.

Если каждый пакет работ «с запасом», резерв невидим и незаметно расходуется. Явный резерв с
обоснованием легче согласовать и проще контролировать.

## Бюджет по времени

Бюджет нужен не только итоговой суммой, но и по периодам — обычно по месяцам. Это нужно:

- финансовой службе — чтобы планировать платежи;
- PM — чтобы сравнивать план и факт каждый месяц, а не узнавать о перерасходе в конце;
- для метода освоенного объёма — плановый объём по периодам и есть базовый план стоимости.

Распределение строится из графика: когда выполняются работы, когда платим подрядчику, когда
закупаем. Платежи подрядчикам часто привязаны к вехам договора — учтите это.

## Практика

Соберите бюджет учебного проекта портала для дилеров на четыре месяца: команда из четырёх человек,
подрядчик по интеграции, хостинг и обучение дилеров. Используйте условные ставки. Распределите
бюджет по месяцам, добавьте резерв на риски с обоснованием по трём рискам из реестра и
управленческий резерв.

<KeyTakeaways>
- Бюджет включает команду, подрядчиков, закупки, эксплуатацию на время проекта, обучение и резервы.
- У каждого пакета работ WBS должен быть источник затрат.
- Оценка по аналогии — на старте, снизу вверх — после детализации; называйте точность оценки.
- Резерв на риски — для известных рисков, управленческий резерв — для непредвиденного.
- Бюджет распределяют по месяцам, чтобы контролировать расход по ходу проекта.
</KeyTakeaways>
