В команде проекта пять человек, и каждый пишет протоколы с ИИ по-своему. У аналитика протоколы
отличные, у двух других — с выдуманными решениями, а один вообще отправляет в модель заметки с
именами клиентов. Каждый изобретает свой промпт и повторяет чужие ошибки. Командная библиотека
превращает личный опыт в общий стандарт.

## Стандарт описания промпта

Промпт без описания — это кусок текста, который непонятно когда и как использовать. Хорошее
описание отвечает на все вопросы пользователя:

| Поле | Что писать |
|---|---|
| Название и назначение | Какую задачу решает: «Протокол встречи по заметкам» |
| Когда использовать и когда нет | «Для рабочих встреч; не для встреч об оценке сотрудников» |
| Текст промпта | С переменными в двойных фигурных скобках |
| Переменные | Что подставлять и в каком виде |
| Пример результата | Обезличенный удачный ответ |
| Что проверить | 3–5 пунктов чек-листа |
| Данные | Что можно и нельзя отправлять, в какие сервисы |
| Владелец и версия | Кто отвечает, номер версии, дата |

Библиотека курса устроена именно так — её можно взять за образец.

## Версии и ревью

Промпты меняются: улучшаются, адаптируются под новые шаблоны, «ломаются» при смене модели. Без
версий непонятно, какой вариант актуален и почему вчера результат был лучше.

Простые правила:

- **Номер версии и дата** у каждого промпта, краткий журнал изменений.
- **Ревью перед изменением.** Изменение общего промпта проверяет второй человек: прогоняет
  тестовые примеры, смотрит результат.
- **Тесты.** У важных промптов есть набор тестовых входов, как у ассистентов.
- **Старые версии не удаляют сразу** — если новая окажется хуже, можно вернуться.

<Callout type="important" title="Промпт — это рабочий инструмент команды">
Относитесь к общим промптам как к шаблонам документов или настройкам трекера: у них есть владелец,
изменения согласуются, а результат проверяется. Иначе любая правка одного человека незаметно
меняет работу всех.
</Callout>

## Где хранить библиотеку

Подойдёт любое место, которое команда уже использует и которое разрешено для таких материалов:
раздел в базе знаний, общий документ с оглавлением, репозиторий. Главные требования:

- быстро найти нужный промпт по задаче;
- видно версию и владельца;
- удобно скопировать текст;
- есть место для обратной связи: «не сработало на таких данных».

## Обучение команды

Библиотека не работает, если ею не пользуются. Что помогает:

- **Короткое введение** на 30–40 минут: как устроена библиотека, правила по данным, как проверять
  результат — на живом примере.
- **Парная работа** — новичок делает протокол с опытным коллегой.
- **Правило «сначала библиотека»** — прежде чем писать свой промпт, проверить, нет ли готового.
- **Канал для находок** — удачные приёмы предлагают в библиотеку, а не хранят у себя.

<Callout type="mistake" title="Спустить библиотеку сверху">
Библиотека, составленная одним человеком без участия команды, воспринимается как ещё одна
обязанность. Соберите первые промпты из того, чем команда уже пользуется, и дайте людям
предлагать свои.
</Callout>

## Метрика: сколько времени экономим

Чтобы понять, работает ли библиотека, измерьте экономию — честно, с учётом проверки.

Для каждого ключевого промпта:

1. **Время без ИИ** — сколько обычно занимает задача вручную.
2. **Время с ИИ** — подготовка данных, запуск, проверка, исправления.
3. **Частота** — сколько раз в месяц задача выполняется командой.
4. **Экономия в месяц** = (время без ИИ − время с ИИ) × частота.

Добавьте качественные показатели: сколько ошибок нашли на проверке, были ли ошибки, ушедшие
адресату.

## Практика

Оформите пять промптов по стандарту: название и назначение, когда использовать, текст с
переменными, описание переменных, пример результата, что проверить, правила по данным, владелец и
версия. Для одного промпта посчитайте экономию времени в месяц с учётом проверки.

<KeyTakeaways>
- Стандарт описания: назначение, когда использовать, текст, переменные, пример, проверка, данные, владелец, версия.
- Изменения общих промптов проходят ревью и прогон тестов; версии хранятся.
- Библиотеку собирают вместе с командой и учат пользоваться на живых примерах.
- Правило «сначала библиотека» сокращает изобретение одних и тех же промптов.
- Экономию считают честно — с учётом времени на проверку и исправления.
</KeyTakeaways>
